Build and run

The repository pins its Go toolchain. Use the build target to produce the payment hub binary.

Terminal
git clone https://github.com/velixio/paymux.git
cd paymux
make build
cp .env.example .env

Set PAYMUX_MASTER_KEY to a base64-encoded random 32-byte key and PAYMUX_BASE_URL to your hub’s address. Keep the master key backed up securely.

./bin/paymux

Create your workspace

Open /setup on your running hub. Enter the one-time code printed in the log, create the administrator, configure 2FA and create an app. The app’s API keys are shown once.

Switch to test mode and add the Simulator provider. It needs no provider credentials. The complete simulator walkthrough includes the local development configuration, webhook receiver and first payment.

Configure routing

Paymux evaluates app rules before organization rules and the catch-all. Accounts must be eligible for the requested mode, currency and purpose. The dashboard’s route tester shows which rule and accounts match.

Keep test and live accounts distinct. Provider capabilities determine whether refunds, subscriptions, mandates or dispute responses are available.

Verify delivery

Your app receives signed events in the Standard Webhooks format. Verify signatures before processing events, handle repeated delivery idempotently, and use the payment API to inspect the authoritative state. A browser redirect alone is not payment confirmation.
